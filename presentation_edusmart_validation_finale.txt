SLIDE 5 : ARCHITECTURE DE L'ONTOLOGIE EDUSMART (5 NIVEAUX & 5 BRANCHES)
--------------------------------------------------------------------------------
[Éléments visuels suggérés]

[Contenu de la slide]
UNE STRUCTURE ONTOLOGIQUE RICHE À 5 NIVEAUX DE SPÉCIALISATION

L'ontologie `Education_Formation` est structurée selon 5 branches principales :

1. Branche Personnes :
   - `Personne` → `Enseignant` (Chercheur, Vacataire, Maître de conférences), `Étudiant` (Licence, Mastère, Ingénieur), `Personnel`.
2. Branche Compétences :
   - `Compétence` → `Technique` (Informatique, Réseaux, Cybersécurité), `Linguistique` (Anglais, Français), `Transversale` (Collaboration, Gestion).
3. Branche Éducation :
   - `Éducation` → `Formation`, `Diplôme`, `Programme_Pédagogique`, `Module`.
4. Branche Apprentissage :
   - `Apprentissage` → `Cours`, `Activité_Pédagogique`, `Évaluation` (Examen, Projet, TP).
5. Branche Établissement :
   - `Établissement` → `Université`, `École_Ingénieur` (ex: ESPRIT), `Centre_Formation`.

Profondeur hiérarchique : Jusqu'à 5 niveaux d'héritage sous la racine commune `owl:Thing`.

[Notes pour l'orateur / Speaker Notes]
"Notre ontologie dépasse la simple hiérarchie plate. Nous avons conçu une ontologie formelle à 5 niveaux de granularité. Par exemple, sous 'Compétence', nous descendons jusqu'à 'Compétence_Technique', puis 'Informatique', 'Programmation', et enfin le langage de programmation spécifique. Cette profondeur permet une précision sémantique maximale lors des requêtes."

AXIOMATISATION & VALIDATION FORMELLE PAR LE RAISONNEUR

• Axiomes de Disjonction (DisjointClasses) :
  - `DisjointClasses(Enseignant, Étudiant)` : Une personne ne peut être simultanément enseignant et étudiant dans le même contexte strict.
  - `DisjointClasses(Compétence_Technique, Compétence_Linguistique)`.

• Axiomes de Restriction (Quantificateurs existentiels & universels) :
  - `Cours subClassOf (développeCompetence some Compétence)` : Tout cours doit développer au moins une compétence.
  - `Étudiant subClassOf (inscritDans exactly 1 Établissement)`.

• Validation formelle avec HermiT 1.4.3 :
  - Cohérence ontologique vérifiée sans contradiction logique (zéro classe insatisfiable).
  - Inférence automatique des sous-classes et classification de la hiérarchie inférée.

[Notes pour l'orateur / Speaker Notes]
"Pour garantir la rigueur formelle de notre modèle OWL 2 DL, nous avons enrichi l'ontologie avec des axiomes de disjonction et des restrictions existentielles et de cardinalité. Nous avons validé l'ensemble sous Protégé avec le raisonneur HermiT : l'ontologie est 100% cohérente et exempte de toute boucle ou incohérence de type."

OPÉRATIONS SPARQL 1.1 EXÉCUTÉES PAR LE SYSTÈME

• 1. Recherche & Filtrage Avancé (SELECT & FILTER) :
  PREFIX edu: <http://www.semanticweb.org/msi/ontologies/2026/9/Education_Formation#>
  SELECT ?personne ?cours ?comp
  WHERE {
    ?personne edu:aAcquis ?comp .
    ?cours edu:développeCompetence ?comp .
    FILTER regex(str(?comp), "Java", "i")
  }

• 2. Création d'individu (INSERT DATA) :
  INSERT DATA {
    edu:yassine_ben_ali a edu:Etudiant ;
      edu:nom "Ben Ali" ;
      edu:prenom "Yassine" ;
      edu:inscritDans edu:ESPRIT .
  }

[Contenu de la slide]
LE TRADUCTEUR INTELLIGENT (NLP TO SPARQL) SANS LLM

• Exigence stricte de Mme Maha MALLEK :
  "L'utilisation directe d'API de LLM clés en main via simple prompt engineering n'est pas autorisée.
   Vous devez développer cette conversion en vous appuyant sur des bibliothèques de NLP/TALN (spaCy, NLTK...)."

• Notre solution technique :
  - Bibliothèque choisie : spaCy 3.7+ avec le modèle de langue française `fr_core_news_sm`.
  - Architecture déterministe basée sur l'ingénierie linguistique :
    1. Analyse morphosyntaxique (Tokenisation, POS Tagging, Lemmatisation).
    2. Extraction d'arbres de dépendance syntaxique (Dependency Parsing).
    3. Reconnaissance d'entités nommées (NER) et détection de patrons (Pattern Matching).
    4. Mapping conceptuel vers les classes et propriétés de l'ontologie EduSmart.
    5. Synthèse automatique d'une requête SPARQL 1.1 valide et exécution immédiate.

[Notes pour l'orateur / Speaker Notes]
"Voici le cœur de notre module de traitement du langage naturel. Nous avons rigoureusement respecté l'interdiction des API de LLM commerciales type OpenAI ou Gemini. Nous avons conçu un traducteur déterministe autonome avec spaCy. Le pipeline extrait la structure grammaticale et les lemmes de la question posée pour construire de manière fiable la clause WHERE et les filtres de la requête SPARQL correspondante."

SLIDE 13 : DÉTAIL DU PIPELINE LINGUISTIQUE SPACY
--------------------------------------------------------------------------------
[Éléments visuels suggérés]
- Exemple analysé pas à pas : "Quels étudiants possèdent la compétence Java ?"
- Tableau montrant : Token | Lemme | POS Tag | Rôle sémantique

[Contenu de la slide]
COMMENT LE PIPELINE TRANSFORME LE LANGAGE NATUREL EN SPARQL

Exemple : « Quels sont les étudiants ayant acquis la compétence Java ? »

Étape 1 : Lemmatisation & POS Tagging (spaCy) :
  - "étudiants" → lemme: `étudiant` | POS: `NOUN` → Cible de classe : `edu:Etudiant`
  - "acquis"     → lemme: `acquérir` | POS: `VERB` → Propriété ciblée : `edu:aAcquis`
  - "Java"       → lemme: `Java`     | POS: `PROPN` → Valeur filtrée : `"Java"`

Étape 2 : Classification d'Intention (Intent Classification) :
  - Détection du type d'opération : `RECHERCHE_COMPETENCE` (Verbes: avoir, acquérir, maîtriser).

Étape 3 : Instanciation du Template SPARQL dynamique :
  SELECT DISTINCT ?nom ?prenom ?comp WHERE {
    ?etudiant a edu:Etudiant ; edu:nom ?nom ; edu:prenom ?prenom ; edu:aAcquis ?c .
    ?c rdfs:label|edu:nomCompetence ?comp .
    FILTER regex(?comp, "Java", "i")
  }

Résultat : Exécution en < 30ms sur Fuseki et affichage direct dans l'interface !

[Notes pour l'orateur / Speaker Notes]
"Ce tableau montre la mécanique interne de notre pipeline spaCy. En combinant l'étiquetage grammatical (POS tagging) et la lemmatisation, notre système identifie le concept recherché, extrait la compétence cible 'Java', et instancie dynamiquement les triplets nécessaires. Ce procédé garantit un résultat déterministe, reproductible et instantané sans aucune dépendance à un service cloud tiers."

VISUALISATION INTERACTIVE DU GRAPHE SÉMANTIQUE

• Pourquoi remplacer le simple OntoGraf de Protégé ?
  - L'OntoGraf classique est statique, difficilement lisible à grande échelle et non intégré au Web.

• Notre solution : Visualiseur de Graphe Intégré (`/graph`) :
  - Rendu interactif en force dirigée (Force-Directed Graph) dans le navigateur.
  - Code couleur sémantique intuitif par catégorie :
    * Bleu : Classes & Hiérarchies
    * Vert : Individus & Personnes
    * Violet : Compétences & Modules
    * Orange : Établissements & Formations
  - Interactions dynamiques : Zoom, déplacement, survol pour afficher les propriétés et relations.
